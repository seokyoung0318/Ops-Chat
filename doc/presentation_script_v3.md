# Ops-Chat 발표 대본 (v3, 슬라이드 19장 기준)

**표시법**
- ⭐ = **꼭 말해야 하는 부분** (평가 항목과 직결, 빼면 감점)
- ➡ = **넘겨도 되는 부분** (화면만 보여 주고 지나가도 됨)
- ⏱ = 예상 시간 · `( )` = 행동 지시(읽지 않음)

**발표 5분 안에 맞추는 방법**: 19장을 전부 설명하지 않는다. **설명하는 장 9개**와 **보여 주고 넘기는 장 10개**로 나눈다.
증거 슬라이드(EVIDENCE)는 "캡처가 있다"는 것을 평가자가 확인할 수 있게 **2~3초씩 띄워 두고 넘어간다.**

| 구분 | 장 | 시간 |
|---|---|---|
| 설명한다 | 1, 2, 4(해결 구조), 8(RAG ①), 12(②+멀티), 15(품질), 17(Before/After), 18(한계), 19(마무리) | 약 4분 30초 |
| 보여 주고 넘긴다 | 3, 5, 6, 7, 9, 10, 11, 13, 14, 16 | 장당 2~3초 |

## 2장. 문제 ⏱ 35초 — 설명한다

시작은 Base 에이전트가 틀리는 두 장면이었습니다.

⭐ **장면 1**: "web-01 CPU 급증 원인 진단해줘"라고 물으면 CPU 매뉴얼이 아니라 DB 다운 매뉴얼을 고릅니다.
코드를 열어 보니 사용자 질문은 안 보고 알림 글자에서 키워드만 찾았고, 하나도 안 맞으면 무조건 db-down을 돌려주게 되어 있었습니다.

⭐ **장면 2**: 목록에 없는 billing-service를 물으면 다른 시스템인 auth-service의 수치로 38초 동안 그럴듯한 답을 만듭니다.

⭐ (잠깐 쉬고) **핵심 문장**: "제가 본 진짜 문제는 틀렸다는 것보다, 틀렸다는 사실이 화면에 드러나지 않는다는 점이었습니다."

➡ 아래 코드 박스는 읽지 않는다. 손으로 가리키기만 한다.

## 8장. 핵심 개선 ① RAG ⏱ 60초 — 설명한다

⭐ 키워드 규칙을 **bge-m3 임베딩 의미 검색**으로 바꾸고, 유사도가 **0.5 미만이면 억지로 고르지 않고 "매뉴얼 없음"**이라고 표시하게 했습니다.

평가는 질문 23개에 정답을 붙이고, 답변 문장이 아니라 **어떤 매뉴얼을 골랐는지**로 채점했습니다. LLM 문장은 매번 달라지기 때문입니다.

(표를 위에서 아래로 가리키며)
- 기존 규칙은 57%
- 질문만으로 검색하니 74%
- ⭐ **알림까지 넣으면 더 좋아질 줄 알았는데 오히려 61%로 떨어졌습니다.** (잠깐 쉬기)
- 원인: 시스템 이름이 없는 질문에서는 기본 조회 대상 auth-service의 "latency" 알림이 검색어에 섞여 엉뚱한 질문까지 전부 지연 매뉴얼로 끌려갔습니다.
- 그래서 **질문에 시스템이 명시될 때만 알림을 쓰는 auto 방식**을 만들었고 **83%**가 나왔습니다.

➡ 아래 숫자(새 runbook 0/5→4/5, 범위 밖 0/3→3/3, 37ms)는 **시간이 남을 때만** 한 문장으로 읽는다.
➡ 오른쪽 코드는 읽지 않는다.

## 12장. 핵심 개선 ② 모르는 시스템 + 멀티 에이전트 ⏱ 50초 — 설명한다

⭐ **모르는 시스템**: 질문에서 시스템 이름을 뽑아 목록과 대조하고, 모르는 시스템이면 **조사와 답변 작성은 건너뛰고** 바로 "조회할 수 없습니다"라고 안내합니다. (질문 분류용 작은 모델 호출 1회만 남습니다.) **38초 오답이 1.8초 안내**가 됐습니다.

⭐ **멀티 에이전트**: 기본값은 기존 방식이고 `PIPELINE=multi`로 바꾸면 새 구조가 돕니다.
- 조사가 실행되는 21문항으로 비교했더니 **정확도는 17개 대 17개로 같았고**
- **조사 라운드는 1.86에서 1.00으로** 줄었습니다.
- **대신 로그 조회가 추가돼 MCP 호출이 한 번 늘었습니다.**

⭐ (반드시) "그래서 '빨라졌다'가 아니라 **'정확도는 유지하면서 되돌아가는 반복을 없앴다'**고 말씀드립니다."

➡ 오른쪽 코드 5줄은 읽지 않는다. ("동시에 시작", "되돌아가기 없음" 주석만 가리킨다.)

## 15장. 품질 장치 ⏱ 45초 — 설명한다

이 수치들을 어떻게 믿을 수 있게 만들었는지 말씀드리겠습니다.

⭐ **의존성 주입**: 모든 노드는 모델, MCP, 검색기를 직접 만들지 않고 **deps로 주입**받습니다.
- 덕분에 테스트에서는 가짜 모델을 끼워 AI 없이 코드 규칙만 검사할 수 있고, **단위 테스트 41개가 약 1초**에 통과합니다.
- ⭐ 또 이 구조 덕분에 **코드를 바꾸지 않고 AI만 Ollama에서 OpenAI로 바꿔** 평균 49초가 5초가 됐습니다. (대가는 한계 슬라이드에서)

⭐ **모듈화**: 나눈 뒤에도 테스트와 평가 결과가 같았고, 통합 테스트가 단위 테스트가 놓친 import 누락 버그를 잡았습니다.

⭐ **LangSmith**: 오른쪽 아래 캡처처럼 한 요청의 흐름이 기록됩니다.

➡ 오른쪽 위 테스트 코드는 읽지 않는다.
➡ [코드 한 줄을 일부러 끄면 그 테스트 하나만 실패했다]는 문장은 **직접 해 보지 않았다면 말하지 않는다.**

## 18장. 한계와 트레이드오프 ⏱ 60초 — 설명한다 (평가 20점 항목)

(슬라이드의 줄을 위에서 아래로 가리키며. 나머지는 발표자 노트에 있다)

⭐ **한계 첫째 — route 오분류**: 작은 모델이 장애가 아닌 질문도 장애로 분류합니다. "사무실 프린터가 인쇄가 안 돼요"가 조사 경로를 탔는데, 유사도가 0.496으로 임계값 0.5 바로 아래라서 간신히 "매뉴얼 없음"으로 끝났습니다.

⭐ **한계 둘째 — 임계값**: 0.5는 임의로 정한 값이라 전 구간을 훑어봤고 0.50~0.54가 좋았습니다. 다만 같은 질문으로 고른 값이라 **유력한 구간이지 최적값은 아니며** 새 질문으로 재보정이 필요합니다.

⭐ **트레이드오프 세 가지**
1. 재조사 최대 한 번, 재작성 최대 세 번으로 **무한 루프는 막았지만**, 상한에 닿으면 불합격 답도 내보냅니다.
2. RAG는 정확도를 올린 대신 **1.2기가 모델과 질문당 수십 ms**를 썼습니다.
3. 모델을 OpenAI로 바꾸면 **평균 49초가 5초**로 줄지만 **과금이 생기고 질문이 외부 서버로 나갑니다**. 빨라진 것은 우리 코드가 아니라 AI를 돌리는 곳이 바뀐 효과입니다.

⭐ **추가 개선**: Hybrid 검색 비교, 새 질문 세트로 임계값 재보정, Human-in-the-loop 구현.

> 시간이 모자라면: **한계 첫째 + 트레이드오프 3번**만 읽고 "나머지는 슬라이드와 노트에 정리했습니다"로 넘긴다.

## 예상 질문 대비 (발표자 노트에도 같은 내용)

- **"멀티 에이전트가 더 나은가요?"** → 정확도는 같다(17/21, 다른 매뉴얼을 고른 질문 0건). 좋아진 점은 재조사·재계획이 없어진 것(조사 라운드 1.86→1.00), 대가는 MCP 호출 1회 증가. 시간은 "빨라졌다"고 말하지 않는다.
- **"정확도가 같은데 왜 바꿨나요?"** → 같은 검색 로직을 쓰니 정확도가 같은 것은 당연하다. 목적은 되돌아가는 루프를 없애 구조를 단순하게 하고, 로그라는 정보 출처를 에이전트로 분리하는 것.
- **"빨라졌나요?"** → 조사 단계 55.9ms vs 49.8ms는 오차 범위. 답변까지 돌린 OpenAI 10문항 4.67초 vs 3.99초는 single에만 있는 시연용 지연(약 0.7초)과 거의 같다. 구조 효과로 말하지 않는다.
- **"Ollama에서 multi가 15초 빨랐는데요?"** → 8개 질문 1회씩이고 질문별 편차가 크다(25~112초, 한 질문은 multi가 14초 느림). 구조가 바꾸는 부분은 1초 미만.
- **"0.5는 어떻게 정했나요?"** → 임의로 정했다. 0.30~0.74 전 구간을 43문항으로 다시 보니 0.50~0.54가 최적 구간(36~37/43), 0.52가 최고. 단 같은 질문으로 고른 값이라 '유력한 구간'. 새 질문 세트로 확인한 뒤에 바꾼다.
- **"route 보정의 부작용은?"** → 시스템 이름이 있으면 모델이 잡담이라 해도 장애로 바꾸므로 설명을 묻는 질문도 장애 경로로 간다(가짜 모델로 재현, 실제 모델은 미측정). 장애를 놓치는 쪽이 더 위험하다고 보고 재현율을 택했다.
- **"프린터 질문은 왜 장애로 분류됐나요?"** → 시스템 이름이 없는 질문이라 보정 코드가 아니라 작은 모델 자체의 오분류. 유사도 0.496이라 임계값 0.5 바로 아래에서 걸러졌다.
- **"루프가 무한히 돌 수 있지 않나요?"** → 재조사 최대 1회, 재작성 최대 3회로 막았다. 대신 3회 불합격해도 답을 내보내고 검수는 형식(30자 이상, 번호)만 본다.

- **"로그 데이터는 진짜인가요?"** → 직접 만든 샘플 데이터다.
- **"83%를 믿을 수 있나요?"** → 개발 세트라 과적합 위험이 있어 검증 20문항(85%)으로 따로 확인했다. 단 20문항이라 1문항이 5%p이고 같은 작성자가 두 세트를 만들었다.
